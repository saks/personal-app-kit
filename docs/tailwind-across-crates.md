# Tailwind across crates

How an app's Tailwind v4.3.3 + daisyUI 5.7.47 build picks up class names, CSS and JS that live in a kit crate pulled in as a git dependency. Decision for [sickness_tracker#90](https://github.com/saks/sickness_tracker/issues/90).

## Decision

Each app runs `scripts/kit-css.sh` (below) in its Trunk `pre_build` hook, after the daisyUI fetch and before `./tailwindcss`. It asks Cargo where each kit crate lives (`cargo metadata --locked`) and writes a gitignored `css/kit.generated.css` with an absolute `@source` per crate, plus the crate's shipped CSS. The app's `input.css` imports that file. No vendoring, no copying Rust sources, no npm. The resolver does need `python3` on every build host (desktop, CI and the machine that runs the Android build); `make check` here and OB's `scripts/check-unit-tests.sh` already need it.

Kit rules that make this work:

- Class names in kit code are full string literals (an enum → `&'static str`). Tailwind scans text, so `format!`-built names are never generated.
- A kit crate that ships CSS puts it in `css/*.css`. A daisyUI theme block uses the placeholder `@plugin "daisyui-theme" {` at the start of a line; the resolver rewrites it to the app's own `daisyui-theme.mjs`. The kit never ships or guesses a plugin path, and both apps keep one pinned daisyUI.
- A kit crate that ships JS puts it in `js/*.js`. The resolver copies it to `public/kit/<crate>/`, which the app already serves with `copy-dir public`, so it loads from `'self'` under `script-src 'self'`.

## App layout

`input.css`:

```css
@import "tailwindcss";
@import "./css/kit.generated.css";

@source "./src/**/*.rs";
@source "./index.html";

@plugin "./daisyui.mjs" {
  themes: false;
}
```

Generated `css/kit.generated.css` (one block per kit crate):

```css
/* kit-theme 0.1.0 from git+https://github.com/saks/personal-app-kit?tag=v0.1.0#<rev> */
@source "/home/<user>/.cargo/git/checkouts/personal-app-kit-<hash>/<short-rev>/crates/kit-theme/src/**/*.rs";

/* kit-theme/css/themes.css */
@plugin "/abs/path/to/app/daisyui-theme.mjs" {
  name: "appLight";
  ...
}
```

`Trunk.toml`:

```toml
[watch]
ignore = ["./src-tauri", "./tailwindcss", "./daisyui.mjs", "./daisyui-theme.mjs", "./output.css", "./css/kit.generated.css", "./public/kit"]

[[hooks]]
stage = "pre_build"
command = "sh"
command_arguments = [
  "-c",
  "./scripts/fetch-tailwind.sh && ./scripts/fetch-daisyui.sh && ./scripts/kit-css.sh && ./tailwindcss -i input.css -o output.css",
]
```

`.gitignore`: add `/css/kit.generated.css` and `/public/kit/`.

`Cargo.toml`: `kit-x = { git = "https://github.com/saks/personal-app-kit", tag = "vX.Y.Z" }`. `Cargo.lock` records the rev; the checkout path in the generated file changes with it.

## Resolver: `scripts/kit-css.sh`

Copy into the app and set `KIT_CRATES` to the kit crates whose classes, CSS or JS the UI uses.

```sh
#!/bin/sh
# Resolve kit crates through Cargo and hand their classes, CSS and JS to the
# Tailwind build. Run from Trunk's pre_build hook, before ./tailwindcss.
#
# For each crate in KIT_CRATES it:
#   - finds the crate's manifest_path with `cargo metadata --locked`;
#   - adds `@source "<crate>/src/**/*.rs"` to css/kit.generated.css;
#   - inlines <crate>/css/*.css, rewriting `@plugin "daisyui-theme"` to the
#     app's own daisyui-theme.mjs;
#   - copies <crate>/js/*.js to public/kit/<crate>/.
# Files are rewritten only when their content changes. Exits non-zero when a
# crate is missing from the dependency graph or resolves more than once.
set -eu

KIT_CRATES="kit-theme"

root="$(CDPATH="" cd -- "$(dirname -- "$0")/.." && pwd)"
cd "$root"

metadata="$(mktemp)"
trap 'rm -f "$metadata"' EXIT
cargo metadata --format-version 1 --locked >"$metadata"

python3 - "$metadata" "$root" $KIT_CRATES <<'PY'
import json, pathlib, re, sys

metadata, root, crates = sys.argv[1], pathlib.Path(sys.argv[2]), sys.argv[3:]
packages = json.loads(pathlib.Path(metadata).read_text(encoding="utf-8"))["packages"]
theme_plugin = root / "daisyui-theme.mjs"
PLACEHOLDER = re.compile(r'^@plugin "daisyui-theme"', re.MULTILINE)

def fail(msg):
    sys.stderr.write(f"scripts/kit-css.sh: {msg}\n")
    sys.exit(1)

def write_if_changed(path, data):
    path.parent.mkdir(parents=True, exist_ok=True)
    if not path.exists() or path.read_bytes() != data:
        path.write_bytes(data)

if not theme_plugin.is_file():
    fail(f"{theme_plugin} is missing; run scripts/fetch-daisyui.sh first")

css = ["/* Generated by scripts/kit-css.sh. Do not edit or commit. */\n"]
for name in crates:
    hits = [p for p in packages if p["name"] == name]
    if len(hits) != 1:
        found = ", ".join(p["id"] for p in hits) or "nothing"
        fail(f"expected exactly one {name} in cargo metadata, found {found}")
    crate = pathlib.Path(hits[0]["manifest_path"]).parent
    src = crate / "src"
    if not src.is_dir():
        fail(f"{name} has no src/ at {crate}")
    css.append(f'\n/* {name} {hits[0]["version"]} from {hits[0]["source"] or "path"} */\n')
    css.append(f'@source "{src.as_posix()}/**/*.rs";\n')
    for sheet in sorted((crate / "css").glob("*.css")):
        body = sheet.read_text(encoding="utf-8")
        body = PLACEHOLDER.sub(f'@plugin "{theme_plugin.as_posix()}"', body)
        css.append(f"\n/* {name}/css/{sheet.name} */\n{body}")
    for script in sorted((crate / "js").glob("*.js")):
        write_if_changed(root / "public" / "kit" / name / script.name, script.read_bytes())

write_if_changed(root / "css" / "kit.generated.css", "".join(css).encode("utf-8"))
PY
```

## Watch behaviour

The generated CSS, `public/kit/` and `output.css` are in `[watch] ignore`, and the resolver rewrites a file only when its content changes, so the hook does not retrigger Trunk. Kit sources live in `~/.cargo/git/checkouts`, outside the watched tree; that is fine because they are pinned by `Cargo.lock` and only change with a tag bump, which is an app `Cargo.toml` edit and triggers a normal rebuild. `cargo tauri dev` runs `trunk serve`, so it gets the same hook. The spike did not separately exercise `trunk serve` / `cargo tauri dev` (descoped by the lead).

## Evidence (spike)

Throwaway consumer (Yew + Trunk 0.21.14 + a minimal Tauri shell) depending on `kit-spike` via `git = …, branch = "spike/tailwind-across-crates"` (rev 13afc8a). `kit-spike` held a component whose classes exist only in that crate (`badge-accent`, `badge-xl`, `badge-warning`, `badge-outline`, `skew-y-3`, `outline-dashed`, `tracking-[0.37em]`), a `css/spike.css` daisyUI theme block and a `js/spike-asset.js`.

| Check | Result |
|---|---|
| `./tailwindcss -i input.css -o output.css` contains every kit-only class and the `kitSpike` theme | pass |
| Negative control: same build with the `@source` line removed | kit classes absent (0 hits) |
| `trunk build`: `dist/output-*.css` has the kit classes and theme; `dist/public/kit/kit-spike/spike-asset.js` present | pass |
| Offline (proxy pointed at a dead port) after the first fetch, including with the checkout dir removed (Cargo re-checks out from `~/.cargo/git/db`) | pass, exit 0 |
| Crate missing from the graph | `expected exactly one kit-missing in cargo metadata, found nothing`, exit 1 |
| Android | not run. The Android frontend is the same `trunk build` run on the host by `beforeBuildCommand`, so the CSS path is identical; Gradle only builds the Rust side |

Gitignored explicit `@source` paths are scanned (the checkout is outside the app repo anyway).
